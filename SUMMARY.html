Architecture

  • Tokenizer: BPE vocab 768 trained only on train_corpus.txt, with raw-byte ids 0–255 as lossless fallback. ~2× sequence compression vs UTF-8 bytes (helps Hindi Devanagari).
  • Model: Causal GPT, n_layer=6, n_embd=160, n_head=5, block_size=256, weight tying, RoPE (no absolute pos table), pre-norm + GELU MLP.
  • Init: GPT-2 style (std=0.02) with residual projections scaled by 1/sqrt(2L).
  • Params: 1,978,880 ≤ 2,000,000 hard cap.

Training recipe (final)

  • AdamW (β=(0.9, 0.95)), weight decay 0.05 on 2D weights only
  • LR 2.5e-3, 150-step linear warmup, cosine decay to 10% of peak
  • Grad clip 1.0, batch 20 (~5120 tokens/step), 2000 optimizer steps, CPU-only PyTorch

Why this beats the baseline

  • Byte tokenizer turns each Devanagari character into ~3 tokens; BPE restores usable context under the same block size.
  • Constant Adam LR with no warmup/clip wastes early steps; schedule + clip stabilizes a much higher peak LR.
  • Unused param budget (~0.66M) and untied head were free capacity; tying + depth use the cap productively.
  • RoPE generalizes better than a tiny learned absolute position table at T=256.
  • Run 2’s larger batch and higher LR beat Run 1 because loss was still decreasing at the step cap.
